# 生产化代码审查

## 结论

当前实现满足动态表格和动态图片循环需求，并已拆分为可供 CLI 或 HTTP 适配器调用的服务库。审查中发现的高风险问题均已修复，没有遗留已知的阻断级缺陷。

## 已修复问题

| 风险 | 修复 |
|---|---|
| 生成失败可能留下损坏输出 | 同目录临时文件写入成功后使用原子替换 |
| 多张模板页被静默删除 | 默认拒绝；仅显式配置后才允许删除额外模板页 |
| 数据规模可耗尽内存或生成超大文件 | 限制表数、行列数、总单元格、输出页数和文本长度 |
| NaN、Infinity 或嵌套对象进入单元格 | 统一值类型校验并返回模板数据错误 |
| 未知 foreach 属性被忽略 | 严格拒绝未知或重复属性，避免拼写错误静默生效 |
| 输出路径覆盖模板 | 显式拒绝输入输出同路径 |
| 纯文本或图片 foreach 被表格引擎误判 | 只接管包含原生 table 的 block |
| 多表页尾被过早拆分 | 完整表放不下时整体换页，只有超出整页才拆分 |
| 私有 API 分散在业务代码中 | 集中到 `pptx_utils.py` 和 `table_renderer.py` |
| 生成逻辑单文件过大 | 拆分配置、模型、解析、校验、兼容层、渲染和服务层 |

## 验证结果

- 55 项自动化测试通过，覆盖表格、图片和统一入口的已确认功能分支。
- 图片需求功能覆盖为 100%（按确认的功能清单计数，不表示所有代码行覆盖率为 100%）。
- Python 编译检查通过。
- Git 空白和补丁格式检查通过。
- `test2-production.pptx` 包结构检查通过，无损坏关系或部件。
- 2 张输出页布局检查通过，无越界或重叠警告。
- 全部表格为可编辑的原生 PowerPoint table。
- 两页均已渲染并逐页检查。
- `test-img-production.pptx` 生成 5 页：图片数组 3 页、逻辑组 2 页。
- 图片测试 PPTX 压缩包完整性和布局溢出检查通过，5 页均已渲染复核。
- 图片与表格混合生成不再产生中间 PPTX，只执行一次最终原子保存。

## 剩余边界

- 动态表格原型不支持合并单元格，检测到后会明确报错。
- 长文本行高使用字体和字符宽度估算；PowerPoint 没有公开的精确排版测量 API，关键模板仍需真实渲染回归。
- 拆列按连续列组进行，不支持把不同列片段横向并排到同一页面。
- 每个图片循环模板页当前支持一个图片循环 block；多个图片循环可放在不同模板页。
- 图片循环原型不支持旋转 Shape；检测到旋转会明确报错，普通单图片替换仍保留原旋转。
- 图片读取仅支持服务器本地栅格文件，不下载网络 URL。
- `python-pptx` 没有公开的幻灯片和完整表格样式克隆 API，因此仍依赖少量私有接口；依赖已限制为 `<2.0`，升级时必须跑完整回归。
- LibreOffice 在当前环境对模板原字体的中文渲染存在缺字；PPTX 内部文本完整，原始模板使用同一渲染器时也存在该问题。
