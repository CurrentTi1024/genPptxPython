# 统一生成入口与自动路由

## API 入口

外部 API 只需要传入模板本地路径、数据对象和输出路径：

```python
from genppt import generate_presentation

result = generate_presentation(
    template_path="/srv/templates/report.pptx",
    data=payload,
    output_path="/srv/output/report.pptx",
)
```

调用方不需要声明模板包含文字、图片还是表格。生成器扫描模板后自动规划处理器。

## 模板识别规则

| Shape 特征 | 分类 | 处理器 |
|---|---|---|
| 文本内容包含 `{{field}}` | 普通文字 | 文本插值处理器 |
| 静态表格单元格包含 `{{field}}` | 普通文字 | 文本插值处理器 |
| 图片名称为 `{{imagePath}}` 或带尺寸后缀 | 普通图片 | 图片替换处理器 |
| foreach block 中包含图片、不包含表格 | 图片循环或图片逻辑组 | 图片网格处理器 |
| foreach block 中包含一个原生表格 | 动态表格逻辑组 | 表格布局处理器 |
| foreach 不包含图片或表格 | 未注册的循环类型 | 生成前明确报错 |
| 没有任何动态标记 | 静态模板 | 原样生成副本 |

普通文字包括文本框、PowerPoint 占位符、组合对象中的文本，以及普通静态表格单元格。动态表格单元格的值由表格处理器填充，不会重复经过根数据插值。

## 处理顺序

```text
读取 template_path
        ↓
验证模板页数、输入输出路径和根数据类型
        ↓
扫描 Shape，生成 TemplatePlan
        ↓
检查冲突、未知 foreach 和模板结构
        ↓
普通静态文字插值
        ↓
图片替换与图片循环
        ↓
动态表格布局与分页
        ↓
一次原子保存到 output_path
```

普通文字先在模板静态元素上完成插值；图片页和表格续页随后克隆这些已处理的静态元素，因此页眉、页脚等根数据仍会出现在所有续页。动态标题、SQL 单元格或图片组文本在生成后不再经过根数据插值，可避免业务数据中恰好出现 `{{...}}` 时被二次解释。

同一模板页不能同时包含图片循环和表格循环。两者都可能独立分页，若共享一页将无法定义稳定的页序和动态区域占用关系；规划阶段会明确报错，模板应将两类循环放到不同页。普通单图片替换可以与动态表格同页使用。

## 单次加载与原子输出

统一入口只加载一次 PPTX，并在内存中完成所有处理。图片和表格混合模板不再保存并重新读取中间 PPTX，从而减少一次完整的 ZIP 解压、压缩和磁盘 IO。

最终文件先写入输出目录中的临时文件，成功后使用原子替换覆盖目标文件。解析、图片校验、布局或保存任一阶段失败时，已有输出文件保持不变。

## 普通文字样式保留

文本插值按 PowerPoint run 执行：

- 占位符位于单个 run 内时，只替换该 run 对应片段。
- 占位符跨多个 run 时，替换值继承起始 run 的字体样式。
- 占位符前后的 run、颜色、粗体和斜体保持不变。
- 数据路径不存在或值为 `null` 时替换为空字符串。

该策略避免把整段文本合并到第一个 run，降低模板局部样式丢失风险。

## 错误隔离

入口在修改演示文稿前执行模板计划检查。无法识别的纯文本 foreach 不会被静默忽略，也不会被普通文字插值误删，而是返回明确的 `TemplateError`。如果需要接入历史项目中的 `if` 或纯文本 foreach 语法，应将对应处理器注册到规划阶段后，再允许该指令通过。

当前仓库已实现并自动路由：普通 `{{}}` 文字插值、普通图片替换、图片循环、图片逻辑组循环和动态表格。历史项目的 `if` 与纯文本 foreach 语法未包含在本仓库源码中，因此本入口不会猜测其语义。

## 复杂度

- 模板扫描与最终文字替换均与 Shape 和文本字符数量近似线性相关。
- 图片校验按解析后的绝对路径缓存，同一路径不会重复解码。
- 表格开销与生成单元格数近似线性相关。
- 图片和表格混合生成只进行一次最终 PPTX 压缩保存。
- 图片数量、图片字节、图片像素、单元格数和输出页数均有硬限制。
