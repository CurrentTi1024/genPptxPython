# 动态表格 PPT 生成需求方案

## 1. 背景

现有 Python 服务基于 `python-pptx` 读取用户制作的 PowerPoint 模板，并通过 `{{ }}` 插值、`if`、`foreach` 等语法替换文本与图片。数据由 Dify 工作流获取、计算后传给 PPT 服务，模板决定最终视觉样式，因此用户无需通过代码复刻企业 PPT 的字体、颜色、Logo、背景和排版。

现新增需求：Dify 执行 SQL 后，按查询结果生成一个或多个原生 PowerPoint 表格。表格的列数、行数和表格数量均可能动态变化。生成后的 PPT 仍需遵循用户提供的企业模板；若同一页放不下，应自动向后续页面流式排版。

## 2. 目标

- 保留现有 Python、`python-pptx`、Dify 工作流和 HTTP API 主链路。
- 用户继续直接在 PowerPoint 中制作样式模板，不要求开发人员在代码中复刻企业样式。
- SQL 结果可以按分类字段分组，动态生成多个“标题 + 表格”块。
- 表格列数、表格数量和数据行数可随 Dify 输出变化。
- 多个表格块优先顺序排列在同一页的指定区域；空间不足时自动生成续页。
- 长表格支持纵向分页，续页重复标题和表头。
- 生成结果以肉眼一致的方式继承模板的布局和视觉风格。

## 3. 非目标与首期边界

首期不处理以下场景：

- 单元格内嵌图片、图标、图表、其他 shape 或嵌套表格。
- 跨分页的合并单元格。
- 任意复杂的表格合并结构。
- 对所有字体和文字长度实现与 PowerPoint 客户端完全像素级一致的自动行高。
- 让动态对象避让页面任意已有对象。

首期仅在模板显式定义的动态区域内排版，不移动 Logo、页眉、主标题、页脚及其他固定模板元素。

当前实现支持同一模板页的多个重复表格 block、内容感知行高、三种列宽策略和列数过多时的连续列分片。

## 4. 总体架构

```text
Dify / SQL
    ↓ 标准化 JSON
PPT HTTP API
    ↓
模板解析器
    ├── 既有文本、图片、if、foreach
    └── 新增动态表格块解析
            ↓
数据标准化与格式化
            ↓
表格测量与分页
            ↓
动态区域流式布局
            ↓
python-pptx 渲染 PPTX
```

职责划分：

| 层级 | 职责 |
|---|---|
| Dify / SQL | 查询、计算、排序、分组、业务口径、输出标准 JSON |
| PPT 服务 | 模板解析、表格结构调整、列宽计算、行高估算、分页、布局、PPTX 生成 |
| PowerPoint 模板 | 企业视觉样式、固定元素、动态区域、标题原型、表格样式原型 |

## 5. 数据契约

PPT 服务不直接消费数据库游标。Dify 输出一个表格数据数组，数组属性名由业务和模板作者自行约定，例如 `tables`、`reasonTables` 或其他名称。模板中 `foreach item` 的值必须与这个外层数组属性名一致。

数组中每个元素代表一个待生成的表格块。系统只保留两个固定属性名：`columns` 和 `rows`。除此之外的属性均为用户自定义业务字段，可选择性地在文本框、图片或其他 shape 中通过 `{{字段名}}` 使用。

```json
{
  "tables": [
    {
      "title": "资料不完整",
      "columns": [
        "区域",
        "数量",
        "涉及金额"
      ],
      "rows": [
        ["华东区", 12, 36000],
        ["华南区", 8, 19000]
      ]
    },
    {
      "reasonName": "流程超时",
      "owner": "运营中心",
      "columns": [
        "区域",
        "数量"
      ],
      "rows": [
        ["华北区", 6]
      ]
    }
  ]
}
```

字段含义：

| 字段 | 是否固定 | 说明 |
|---|---:|---|
| `columns` | 是 | 表头数组，同时决定目标表格列数 |
| `rows` | 是 | 数据行数组，同时决定目标表格数据行数；可为空。支持二维数组，也支持按列名取值的对象数组 |
| 其他字段 | 否 | 名称与含义完全由用户定义，如 `title`、`reasonName`、`owner`、`tableName` 等 |

PPT 服务不要求 Dify 输出 `id`、`tableName` 或 `title`。如果用户希望显示标题，可以自行输出任意字段，例如 `title` 或 `reasonName`，并在模板文本框中写对应的 `{{title}}` 或 `{{reasonName}}`。如果用户希望动态设置生成后 shape 的名称，也可以自行提供字段并在 shape name 中引用；未提供时由服务端生成内部名称。

`columns` 和 `rows` 不需要在 PPT 模板中显式引用。只要原生表格 shape 参加该 `foreach block`，引擎就会自动读取当前循环元素的 `columns` 和 `rows`。

## 6. 模板设计

### 6.1 动态区域

首期使用单一模板页，不区分首页模板和续页模板。发生分页时，生成器复制当前模板页，并在新页面继续生成剩余表格。

动态区域默认由同一 `foreach block` 内所有原型 shape 的水平范围、顶部位置以及页面底部安全边距共同推导，因此模板作者无需额外增加 `flow` 标记。服务端同时允许通过运行参数覆盖动态区域和底部安全边距，便于适配特殊模板。

页面中的 Logo、页眉、页脚、主标题等固定元素随模板页一起复制；`foreach` 原型不会作为普通固定元素复制，而是在每一页根据数据重新生成。

### 6.2 动态表格块

一个动态表格块在 PowerPoint 中由多个独立 shape 构成，通常包括：

- 标题文本框。
- 原生 PowerPoint 表格。
- 可选的说明文本、图标、装饰线或备注文本框。

PowerPoint 中无需也不应要求将文本框与 table 物理组合。`python-pptx` 的公开 API 不能将原生 table 加入 group shape；服务端通过相同的循环标记将它们作为一个逻辑块处理。

如果业务需要标题，可以添加标题文本框，其 shape name 例如：

```text
<foreach item=tables block=reasonTable>{{title}}</foreach>
```

表格的 shape name 可以只声明循环与逻辑块：

```text
<foreach item=tables block=reasonTable></foreach>
```

标题文本框正文可以引用用户自定义字段：

```text
{{title}}
```

也可以使用其他字段：

```text
{{reasonName}}
```

表格原型的单元格可放示例文字，用于让模板作者查看效果；实际生成时表头与数据单元格会被替换。

### 6.3 指令字段定义

```text
<foreach item=tables block=reasonTable>...</foreach>
```

| 字段 | 来源与规则 |
|---|---|
| `item` | Dify 输出 JSON 中的数组路径，如 `tables` 或 `report.reasonTables` |
| `block` | 用户自定义的逻辑组合名称。相同 `item` 和相同 `block` 的 shape 归属同一动态块 |
| 指令正文 | 可对当前循环 item 的任意用户字段求值；对文本 shape 可省略，仍由文本框正文中的插值替换内容 |

`block` 建议仅允许字母、数字、下划线和连字符。相同 `block` 但不同 `item` 视为模板错误，避免把不相关的数组错误组合。

不使用 `role` 字段。引擎根据 shape 类型推断处理方式：

| shape 类型 | 渲染方式 |
|---|---|
| 文本框、占位文本框 | 复制并替换 `{{ }}` 表达式 |
| 原生 PowerPoint Table | 隐式读取当前 item 的 `columns` 与 `rows`，将模板表格扩缩为对应行列数并填充数据 |
| 图片 | 后续扩展为替换图片地址或二进制内容 |
| 普通 shape、线条 | 原样复制，作为该 block 的装饰元素 |

首期约束：同一个 `(item, block)` 最多包含一个原生表格。多个 table 的组合需求后续再扩展。

### 6.4 模板页与续页

模板作者只需制作一张页面。生成器执行规则：

1. 第一张输出页直接使用该模板页。
2. 发生分页时，复制同一模板页的版式和固定对象。
3. 从复制页中排除所有 `foreach` 原型，再生成当前页需要的表格片段。
4. 每张续页重复表头；可选标题或说明 shape 可按配置重复。
5. 不需要 `page=first`、`page=continuation` 或其他续页标记。

如果某个对象只允许出现在第一页，可在后续版本增加简单的 `<firstOnly>` 标记。首期测试模板没有此需求，暂不增加额外语法。

## 7. 逻辑模型

解析模板后，系统不按 shape 单独循环，而是先编译为逻辑块：

```python
RepeatBlock(
    item_path="tables",
    block_name="reasonTable",
    prototype_shapes=[title_textbox, table, optional_note],
    inferred_region=Region.from_prototype_shapes(...),
)
```

每个 `tables[i]` 生成一个 `TableBlock`。标题和其他附属 shape 均为可选，只有原生表格及其 `columns`、`rows` 是动态表格场景的固定内容：

```text
TableBlock
├── 可选标题或业务说明 shape
├── 表格 shape（固定）
└── 可选装饰 / 备注 shape
```

表格过长时，一个 `TableBlock` 会拆成多个 `TableFragment`：

```text
TableBlock
├── Fragment 1：可选标题 + 表头 + 第 1～N 行
├── Fragment 2：可选续页标题 + 表头 + 后续行
└── Fragment 3：可选续页标题 + 表头 + 最后行
```

## 8. 表格样式与动态列

模板中的原生表格既是位置占位，也是视觉样式原型。模板作者应至少设计：

- 表头行。
- 普通数据行。
- 可选奇偶行样式。
- 可选标题文本框样式。

当前 [test.pptx](../tests/fixtures/test.pptx) 的表格原型为 4 行 7 列，可将第一行视为表头样式，其余三行视为数据行样式原型。实际生成表格的目标列数为 `len(columns)`，目标行数为 `1 + len(rows)`，其中第一行为表头。

### 8.1 行列数量调整

模板表格行列数与数据不一致时，引擎必须调整到精确匹配：

```text
target_columns = len(columns)
target_rows = 1 + len(rows)
```

- 模板列数多于 `target_columns`：删除多余列。
- 模板列数少于 `target_columns`：增加缺少的列。
- 模板行数多于 `target_rows`：删除多余数据行。
- 模板行数少于 `target_rows`：增加缺少的数据行。
- `rows` 为空时，跳过整个表项，不生成标题或表格。
- 调整后必须填满全部 `columns` 与 `rows`，不得因模板原始行列不足而截断数据。

删除和增加只改变表格结构及尺寸，不改变模板定义的字体、字号、文字颜色、填充、边框、内边距、对齐方式和行列风格。

### 8.2 新增行列的样式继承

新增行列默认继承模板表格原有样式：

- 第一行始终继承模板第一行的表头样式。
- 数据行按模板现有数据行样式循环继承；若模板只有一个数据样式，则所有新增行均复制该样式。
- 第一列继承模板第一列样式。
- 最后一列继承模板最后一列样式。
- 中间新增列继承模板中间列样式；若模板没有独立中间列，则复制最接近的数据列样式。
- 删除行列后，最终表格仍应正确保留首列、末列和外边框效果。
- 表格整体位置与宽度默认沿用模板；新增或删除列后，在模板总宽度内重新分配列宽。

样式复制以用户肉眼一致为验收目标。若模板使用奇偶行底色，则新增数据行继续遵循原有交替规律。

### 8.3 动态列宽

动态列使用位置样式策略：

```text
1 列：first_last
2 列：first + last
3 列：first + middle + last
4 列及以上：first + middle × N + last
```

列宽支持模板比例、内容权重和等宽三种策略。系统始终保持模板表格总宽度；当全部列无法满足最小可读宽度时，按原列顺序拆成多个列片段，并可在每个片段中重复前 N 个标识列。

## 9. 动态区域排版与分页

### 9.1 排版范围

布局引擎在模板原型推导出的动态区域中自上而下排列动态块。默认顶部为原型 block 顶部，左右范围为原型 block 的范围，底部为幻灯片高度减去安全边距。

```text
固定页眉 / Logo / 主标题
────────────────────────────
动态区域：可选业务文本 + 表格块顺序流式排列
────────────────────────────
固定页脚 / 页码
```

### 9.2 单个表格块高度

```text
block_height =
  可选业务文本或附属 shape 高度
  + 附属 shape 与表格间距
  + 表头高度
  + 数据行高度之和
  + 下一个块的间距
```

系统根据列宽、字体、字号、内边距和中英文字符宽度估算换行数及行高。`wrap` 保持字号并增高；`shrink`、`truncate`、`error` 提供明确的溢出处理。由于 PowerPoint 没有公开的精确排版测量 API，关键模板仍需通过真实渲染回归校准。

### 9.3 放置规则

1. 依照 Dify 输出 `tables` 的顺序处理表格块。
2. 当前页放得下完整块时，直接放置。
3. 当前页放不下完整块时，默认整块移到下一页，不使用当前页的零散剩余空间。
4. 新页能放下完整块时，整张表保持完整，不拆分。
5. 只有单块本身超过一张完整页面的可用高度时，才按数据行拆分为多个片段。
6. 续页复制同一模板页的版式和固定元素，并排除 `foreach` 原型。
7. 续页必须重复表头；如果 block 中存在标题或说明文本框，则可按配置重复这些 shape 并追加“（续）”。
8. 同一页某个完整表格结束后，如剩余空间能容纳下一张完整表格，则继续放置下一张表。

### 9.4 避免难看分页

默认策略：

```python
TableLayoutPolicy(
    keep_optional_prefix_shapes_with_table=True,
    minimum_first_fragment_rows=2,
    repeat_header=True,
    repeat_optional_prefix_shapes=True,
    continuation_suffix="（续）",
    minimum_last_page_rows=2,
    block_gap_pt=12,
)
```

含义：

- 如果存在标题或说明 shape，其后至少保留两行数据，否则整块移到下一页。
- 续页必须重复表头；可选业务文本是否重复由策略控制。
- 避免最后一页只剩一行数据；必要时从前页回拨一行或多行。
- 相邻表格块之间保留模板定义的间距或默认间距。

## 10. 生成流程

```text
1. 读取模板 PPTX
2. 解析既有插值、if、foreach 指令
3. 扫描所有带 foreach 指令的 shape
4. 以 (item, block) 分组，形成 RepeatBlock
5. 读取 Dify JSON，解析 item 对应数组
6. 对每个数组元素：
   a. 替换文本、图片等普通 shape 的表达式
   b. 用 columns / rows 生成原生表格
   c. 计算 TableBlock 实际高度
   d. 在动态区域尝试放置
   e. 必要时拆表、创建续页、重复表头及可选附属 shape
7. 删除模板原型
8. 保存输出 PPTX
9. 使用 LibreOffice 或 PowerPoint 渲染进行视觉回归检查
```

## 11. Python 实现建议

保留 `python-pptx` 作为主实现库。

当前实现模块：

```text
config.py          - 页面策略与资源限制
directives.py      - foreach 和插值解析
data.py            - columns / rows 校验与规范化
models.py          - RepeatBlock 等领域模型
pptx_utils.py      - 幻灯片与 shape 克隆兼容层
table_renderer.py  - 原生表格创建与样式复制
service.py         - 分页布局、原子保存和公共服务入口
cli.py             - 命令行适配器
```

实现原则：先完成分页计算，再一次性创建该页片段准确行列数的表格；不要在已创建的表格中不断追加数据行。

`python-pptx` 对单元格字体、填充、内边距、对齐、列宽、行高和合并单元格支持较好。四边不同边框等完整表格样式复制可能需要单独评估：首期可限定为公开 API 支持的样式；若企业模板的边框保真无法满足，再封装受控、只复制样式节点的适配层，而不允许业务代码任意操作 PPTX XML。

## 12. 模板校验规则

服务端在生成前应返回清晰的模板错误：

| 校验项 | 错误条件 |
|---|---|
| 动态区域 | 无法从原型 shape 推导有效区域，或区域宽高为零 |
| 循环指令 | foreach 语法不合法 |
| 逻辑块 | 同一 `(item, block)` 为空、其 `item` 不一致，或多个 block 的原型矩形相互重叠 |
| 表格数量 | 同一 block 中超过一个原生表格 |
| 数据路径 | `item` 指向的数据不是数组 |
| 表格数据 | 缺少 `columns`、`rows`，数据结构不符合约定，或超过资源限制 |
| 合并单元格 | 动态表格原型存在合并或被合并的单元格 |
| 列数 | 表格本身小于单列最小宽度，或重复列占满整个列片段 |
| 单行高度 | 单一数据行高于整页可用区域，且未配置截断或缩放策略 |

## 13. 验收样例

至少准备以下模板与数据组合：

1. 单表、3 至 5 行，验证可选业务文本、表头、数据和样式。
2. 单表、超过一页，验证可选业务文本、重复表头、行不被错误切开。
3. 多表、每表较短，验证多个块优先放入同一页。
4. 多表，其中一张长表，验证长表结束后下一张表继续填充剩余空间。
5. 每张表列数不同，验证 2、5、8 列的宽度和对齐。
6. 长文本、空值、数字和日期值，验证文本转换、换行及表格完整性。

验收标准：固定模板元素位置不变；表格块顺序与输入一致；可选业务文本不单独出现在页尾；续页正确；字体和颜色肉眼符合模板；没有重叠、越界、数据缺失或不可读的过窄列。

## 14. 分期计划

### 第一阶段：最小可用版本

- 解析 `item` 与 `block`。
- 文本框 + 单个原生 table 的逻辑组合。
- 固定动态区域中的纵向流式排列。
- 动态列与动态行。
- 可选业务文本、表头、普通数据行。
- 单表纵向分页、可选附属 shape 和重复表头。
- 基础值转换与模板校验。

### 第二阶段：样式和模板能力完善

- 奇偶行、合计行、条件色。
- 独立的首页模板与续页模板。
- 备注、图标和图片等 block 内附属 shape。
- 基于 PowerPoint 客户端的更精确文字测量与行高校准。
- 表格边框与高级样式保真适配。

### 第三阶段：复杂报表

- 多个原生表格组成一个 block。
- 图表、图片和表格混排。
- 模板编辑器或模板检查工具。

## 15. 待确认事项

以下事项会影响首期实现细节，建议在开发前确认：

1. 单张表在真实业务中的最大列数是多少？如果可能达到 15 至 20 列，需要提前设计横向拆表或宽页模板。
2. 单元格文本的典型和最大长度是多少？是否允许自动换行、截断或缩小字号？
3. 默认推荐 `columns: ["列1", "列2"]`、`rows: [[值1, 值2], ...]`；兼容 `rows` 为对象数组的形式。
4. 表格顺序应由 Dify 排好，还是 PPT 服务按标题、数据量或其他规则排序？
5. 续页是否允许继续使用首页的主标题，还是需要专用续页模板？
6. 是否需要合计行、空表提示、负数变色、阈值高亮等业务规则？
7. 当前实现中，二维数组某行的值数量与 `columns` 不一致时直接报错；对象数组缺失的列补空字符串。
