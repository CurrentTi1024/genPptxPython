# 模板驱动 PPT 生成方案与实现

## 1. 目标与范围

本项目从用户提供的企业 PPTX 模板生成制式演示文稿。模板负责视觉样式和页面结构，数据由 Dify 工作流、SQL 或其他业务服务提供。系统只替换或复制模板中的元素，不在代码中复刻企业字体、颜色、边框和背景。

统一服务入口接收三个核心参数：

```python
generate_presentation(template_path, data, output_path, config=...)
```

- `template_path`：服务器本地 PPTX 文件路径。
- `data`：根对象，通常直接使用 Dify 工具输出。
- `output_path`：生成文件路径。
- `config`：可选的布局策略、资源限制和图片访问范围。

当前实现覆盖普通文字插值、单图片替换、图片循环、图片逻辑组循环和动态原生表格。历史系统中的 `if` 和纯文本 foreach 尚未迁入本仓库。

## 2. 核心设计

### 2.1 模板承担样式

PowerPoint 模板中的 Shape 是样式原型：

- 文本框提供字体、字号、段落、颜色和位置。
- 图片占位 Shape 提供位置、尺寸、旋转、边框和阴影。
- 原生 table 提供表头、数据行、交替行、边框和单元格内边距。
- 非动态 Shape 作为页眉、页脚、背景或企业固定内容被续页复制。

系统使用 `python-pptx` 公开 API 完成常规读写。幻灯片复制、关系复制和完整表格样式克隆没有稳定公开 API，相关私有接口集中在 `pptx_utils.py` 和 `table_renderer.py`。

### 2.2 数据与模板分离

SQL 查询、分类归纳和业务计算在 Dify 或上游服务完成。PPT 服务不执行 SQL，只接受整理后的 JSON 数据。数据工作流、企业模板和生成服务可以独立维护。

### 2.3 逻辑 block

多个 Shape 使用相同的 `item + block` 时组成一个逻辑循环单元，无需在 PowerPoint 中物理组合：

```text
<foreach item=tables block=reasonTable>{{title}}</foreach>
<foreach item=tables block=reasonTable>{{shapeName}}</foreach>
```

系统根据 Shape 类型判断职责，不需要 `role=title/table/image`：

- 原生 table 进入表格处理器。
- 图片 Shape 进入图片处理器。
- 其他 Shape 作为当前数据项的标题或说明。

`block` 名由模板设计者自定义，只用于关联同一循环中的 Shape。

## 3. 模板语法

### 3.1 普通文字

文本框、占位符、组合对象中的文本和静态表格单元格均支持：

```text
{{field}}
{{report.title}}
```

路径缺失或值为 `null` 时显示为空字符串。替换按 text run 进行，占位符跨 run 时，替换值继承起始 run 的样式，其余文字样式保持不变。

### 3.2 单图片

将图片 Shape 名称设置为：

```text
{{imagePath}}
{{imagePath}}(x)
{{imagePath}}(y)
{{imagePath}}(x,y)
```

| 模式 | 行为 |
|---|---|
| 默认或 `(x)` | 宽度保持模板值，高度按原图比例计算 |
| `(y)` | 高度保持模板值，宽度按原图比例计算 |
| `(x,y)` | 长宽均使用模板值，允许拉伸 |

路径为空、字段不存在、文件不存在或图片无法解码时，系统删除占位图。

### 3.3 图片循环

路径字符串数组：

```json
{"imgs": ["/data/a.png", "/data/b.png"]}
```

```text
<foreach item=imgs></foreach>(x)
```

对象数组和逻辑组：

```text
<foreach item=imageGroups block=equipment>{{title}}</foreach>
<foreach item=imageGroups block=equipment>{{imagePath}}</foreach>(x,y)
```

`rows` 和 `cols` 均为可选正整数，可以只设置其中一个：

```text
<foreach item=imgs rows=2></foreach>
<foreach item=imgs cols=3></foreach>
<foreach item=imgs rows=2 cols=3></foreach>
```

未设置时，系统根据逻辑组尺寸和页面剩余区域计算网格。数据超过单页容量时复制固定元素并分页。逻辑组中任一必需图片无效时，系统跳过整个数据项。

### 3.4 动态表格

标题 Shape 和原生 table 使用相同的 `item + block`。`item` 指向根数据中的数组：

```json
{
  "tables": [
    {
      "title": "资料不完整",
      "columns": ["区域", "数量"],
      "rows": [["华东", 12], ["华南", 8]]
    }
  ]
}
```

每个表项只有 `columns` 和 `rows` 是固定字段。`title`、用于 Shape 名称的字段和其他说明字段都由模板设计者自行定义，只要模板表达式和数据字段对应即可。

系统按照实际数据列数和行数调整表格：

- 模板行列多于数据时删除多余行列。
- 模板行列少于数据时增加行列。
- 新增单元格继承模板表头和数据行样式。
- 输出仍是可编辑的原生 PowerPoint table。

列定义可为字符串，也可包含 `key`、`label`、`format` 和 `nullValue`。表项可使用 `_table` 配置列宽、最小列宽、重复首列、空值和文本溢出策略。

## 4. 自动识别和执行顺序

模板加载后，`planner.py` 扫描每个 Shape：

| 判断条件 | 分类 |
|---|---|
| 文本或静态单元格含 `{{...}}` | 普通文字 |
| 图片名称为单变量表达式 | 单图片 |
| foreach block 含图片且不含 table | 图片循环 |
| foreach block 含一个原生 table | 动态表格 |
| foreach 不含图片和 table | 未注册语法，拒绝生成 |

执行流程：

```text
验证路径、根数据和模板页数
扫描模板并检查指令冲突
处理模板中的普通静态文字
替换单图片并扩展图片循环
扩展动态表格并完成分页
写入临时 PPTX
原子替换目标文件
```

普通文字先处理，续页会复制已完成根数据插值的页眉和页脚。动态数据生成后不再进行根数据插值，避免 SQL 值中出现字面量 `{{...}}` 时被二次解释。

## 5. 表格布局与分页

### 5.1 多表排版

同一 block 的表格按数据顺序向下排列：

1. 完整表格能放进当前剩余空间时留在当前页。
2. 当前页放不下但新页能完整容纳时，整张表移到新页。
3. 表格本身超过完整页面区域时，按数据行拆页并重复表头。
4. 一个数据行在完整区域也放不下时返回模板错误。

### 5.2 多个表格 block

同一模板页允许多个动态表格 block。系统根据 block 的位置和水平方向相交关系推导各自动态区域。上下 block 互不侵占；左右并排 block 可分别向下排版；实际矩形重叠会在预检阶段报错。

### 5.3 长文本和宽表

行高根据有效列宽、字体、内边距和中英文字符宽度估算。支持：

- `wrap`：保持字号并增加行高。
- `shrink`：缩小到最小字号，必要时省略。
- `truncate`：保持字号并添加省略号。
- `error`：超过配置高度时拒绝生成。

列宽支持 `template`、`content` 和 `equal`。当列数导致列宽低于最小可读宽度时，系统按连续列组拆分，并可在后续片段重复前 N 列。

### 5.4 续页标题和名称

循环 Shape 文本可使用：

```text
{{title}}{{_page.continuationSuffix}}
```

系统提供是否续页、行分页序号和列分页序号等 `_page` 上下文。每个生成 Shape 的名称包含 block、数据项、列片段和行片段序号，以保证唯一性。

## 6. 图片布局与分页

图片循环使用模板逻辑组的外接区域作为单元尺寸。自动网格根据页面右侧和底部剩余空间计算行列；显式 `rows` 或 `cols` 会锁定对应维度，必要时等比缩小整个组。

一个图片循环模板页当前只允许一个图片循环 block。一个 PPTX 可以在不同模板页定义多个图片循环。图片循环和表格循环不能位于同一模板页，因为两者都有独立分页器；普通单图片不受此限制。

循环图片原型暂不支持旋转。普通单图片替换可以保留模板旋转。

## 7. 空数据策略

- 图片变量为空或图片不可读取：删除普通图片占位 Shape。
- 图片循环数组为空：删除该循环的全部原型 Shape。
- 图片逻辑组的必需图片无效：跳过该组数据项。
- 表格外层数组为空：不生成该 block 的标题和表格。
- 某个表项 `rows=[]`：跳过该表项及其标题、说明和表格。
- 非动态企业固定元素继续保留。

## 8. 生产安全与性能

`GeneratorConfig` 提供以下默认硬限制：

| 资源 | 默认值 |
|---|---:|
| 图片数量 | 1,000 |
| 单图片大小 | 25 MB |
| 唯一图片总大小 | 250 MB |
| 单图片解码像素 | 40,000,000 |
| 输出幻灯片 | 500 |

表格数量、行列数、总单元格和单元格文本长度也有独立限制。HTTP 服务应配置 `allowed_image_roots`，只允许读取上传目录和企业素材目录。系统解析符号链接后再检查目录边界。

图片验证结果按绝对路径缓存，同一路径不会重复解码。单次请求只加载一次 PPTX，图片和表格之间不生成中间文件。所有状态都属于单次调用，没有共享可变全局状态；高负载部署建议使用进程池隔离 CPU 和内存。

输出采用同目录临时文件和 `os.replace`。模板解析、数据校验、图片读取、布局或保存失败时，不会破坏已经存在的目标文件。

## 9. HTTP 服务集成建议

HTTP 层应完成以下工作：

1. 验证并保存上传的模板和图片。
2. 将 Dify 传入的 JSON 解析为对象。
3. 为每个请求创建独立输出目录。
4. 调用 `generate_presentation()`。
5. 将 `TemplateError` 映射为可读的 4xx 响应，将未知异常记录后返回 5xx。
6. 任务完成后按保留策略清理上传文件和临时输出。

不要允许客户端直接指定任意服务器路径。模板路径和图片路径应从服务端签发的任务目录中解析，并结合 `allowed_image_roots` 限制读取范围。

## 10. 代码结构

| 模块 | 职责 |
|---|---|
| `service.py` | 统一入口、动态表格流式布局和原子保存 |
| `planner.py` | 模板扫描、自动分类和冲突检查 |
| `directives.py` | 严格解析表达式和 foreach 属性 |
| `text_renderer.py` | 保留 run 样式的普通文字插值 |
| `image_renderer.py` | 图片校验、替换、逻辑组网格和分页 |
| `data.py` | 表格数据校验、空值、数字和日期格式化 |
| `table_renderer.py` | 行高、列宽、拆列、溢出和样式复制 |
| `pptx_utils.py` | Shape、Slide 和关系复制兼容层 |
| `config.py` | 布局参数和资源限制 |
| `models.py` | 指令、block 和规范化数据模型 |

当前 55 项测试覆盖普通文字和跨 run 样式、表格布局与分页、图片四种尺寸模式、图片循环与网格、空值和资源限制、自动路由、模板冲突和失败保护。

## 12. 已知边界

- 动态表格原型不支持合并单元格。
- PowerPoint 没有公开的精确文字测量 API，长文本行高使用保守估算。
- 拆列按连续列组生成，不会将不同列片段横向并排在同一页。
- 同一模板页不支持图片循环与表格循环共同分页。
- 每个图片循环模板页只支持一个图片循环 block。
- 图片循环原型不支持旋转。
- 图片只支持服务器本地栅格文件，不下载网络 URL。
- 纯文本 foreach 和 `if` 尚未注册到当前入口。
- 项目依赖少量受控 `python-pptx` 私有 API，升级主版本前必须执行完整回归。
